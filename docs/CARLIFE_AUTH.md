# CarLife 2.1 и старшие версии

В сборке 0.6.0 версию ГУ можно выбрать в разделе **Приборка и HUD → Протокол CarLife**. Доступны Honda 2.0 и профили с авторизацией 2.1, 3.0, 3.1, 4.0 и 4.1. Выбор действует для USB, Wi-Fi, тестового TCP и демо. Для существующих установок первым остаётся Honda.

## Подключение HSD

1. На телефоне откройте **HSD** и выберите CarLife по USB или Wi-Fi. Если Android показывает приложения для USB-аксессуара, выберите HSD.
2. В эмуляторе выберите, например, **CarLife 2.1 · с авторизацией**. Для HSD 0.8.4-rc12 оставьте поле канала пустым, CUID автоматически созданным и флажок обязательного шифрования снятым. HSD этой версии отвечает на проверку телефона и принимает команды темы. Обмен ключом содержимого в его реализации пока отсутствует.
3. Нажмите **Подключить**. HSD запоминает версию до закрытия своего сеанса аксессуара. Для смены версии по USB отключите эмулятор, завершите сеанс HSD и переподключите кабель. После этого подключите эмулятор с новой версией.

В диагностическом JSON блок `carlife_negotiation` показывает версию запроса, номер протокола, если его сообщил телефон, решения обеих сторон, состояние шифрования, активацию OEM и последнюю тему, полученную от телефона. Значение `null` у результата означает, что ответ ещё не пришёл. Номер версии ГУ задаёт оператор, отказ телефона завершает попытку. Для запуска из командной строки можно передать `--profile carlife-4.1`.

## Телефон с проверкой головного устройства

Используйте канал Baidu, выданный для вашего проекта, и его CUID, если поставщик привязывает допуск к конкретному ГУ. Эти поля передаются телефону в `STATISTIC_INFO`. Эмулятор создаёт локальный CUID при первом запуске и сохраняет его в настройках. Решение о допуске принимает телефон.

Для проектов с выданным сертификатом или регистрацией автомобиля кнопка **Файл активации OEM → Обзор** принимает локальный JSON в UTF-8 размером до 32 КиБ. Укажите только поля, выданные для этой интеграции.

| Поле JSON | Назначение |
| --- | --- |
| `certificate` | Строковое значение сертификата ГУ в формате поставщика, до 24 000 байт. Можно передать отдельно. |
| `uuid`, `vehicle_id` | Пара идентификаторов для запроса активации. Требуется заполнить также поле **Канал OEM**. |
| `bt_address` | Адрес Bluetooth, если он входит в регистрацию с UUID. |

После согласования версии эмулятор передаёт предоставленный сертификат в `HU_CERTIFICATE` и, при наличии UUID, отправляет `HU_ACTIVE_INFO`. Для этой ветви запуск видео требует положительного `MD_ACTIVE_DONE`. Отрицательный результат останавливает сеанс. В официальном мобильном приложении 8.9.5 у получения сертификата отдельного положительного ответа не обнаружено. Поэтому отчёт отдельно показывает, был ли указан сертификат, и результат активации. В настройках хранится путь к файлу. Журнал пакетов профилей с авторизацией сохраняет типы, размеры и хеши, а сырые потоки USB/TCP отключены, поскольку пакеты могут содержать идентификаторы и сертификат.

Промышленное подключение и выдачу проектных данных выполняет Baidu. Работа онлайн-активации конкретного OEM требует действующей регистрации и проверки с его мобильным клиентом. [Подключение автопроизводителей к Baidu CarLife](https://online.carlife.baidu.com/carlife/caroem/start)

## Обмен при подключении

| Этап | Поведение эмулятора |
| --- | --- |
| Версия | Отправляет `HU_PROTOCOL_VERSION` с выбранными major/minor и ждёт `VERSION_MATCH`. У Baidu 8.9.5 проверка совместимости сравнивает major. SDK для ГУ по умолчанию предлагает 4.1. |
| ГУ проверяет телефон | При получении `MD_INFO` фиксирует поля brand, model и sdk данного сеанса. Отправляет новый запрос `2.0;<nonce>`, проверяет контрольный ответ телефона по алгоритму SDK и возвращает результат в `HU_AUTHEN_RESULT`. Эта проверка совместимости использует MD5 и не устанавливает подлинность производителя телефона. |
| Телефон проверяет ГУ | Обрабатывает отдельный `MD_AUTHEN_RESULT` и подтверждает получение сообщением `0x1804C`. Видео начинается после обоих положительных решений и завершения запрошенных процедур. Максимальное ожидание авторизации составляет 30 секунд. |
| Шифрование | При выборе **Требовать шифрование RSA/AES** или запросе `CONTENT_ENCRYPTION=1` от телефона эмулятор ожидает завершения обмена ключами перед запуском видео. ГУ создаёт свежую пару RSA-2048, принимает обёрнутый ключ AES и переключает кодек пакетов после `MD_ENCRYPT_READY`. По правилам SDK шифруются непустые полезные данные, заголовки каналов остаются открытыми. |
| Дополнительные функции | Эмулятор объявляет мультитач согласно настройке ввода, передаёт выбранную дневную или ночную тему и запрашивает тему телефона. Приборка подписывается на навигацию и музыку. По Wi-Fi дополнительно проверяется порт 9440 канала UPDATE. Основные шесть каналов работают и на телефонах без 9440. Установка прошивок по UPDATE не реализована. |

Тест с отдельным собеседником на сокете проводит обмен RSA/AES, передаёт зашифрованное видео H.264 и проверяет команды клавиши и темы.

## Проверка с HSD 0.8.4-rc12

На Samsung со сборкой HSD 132 по USB обе стороны подтвердили авторизацию, эмулятор получил тему и декодировал видео в профилях 2.1 и 4.1. В сеансе 2.1 получено 318 кадров. В финальной сборке профиль 4.1 показал Навигатор и Яндекс Музыку в разрешении 1280×720. За 72 секунды эмулятор декодировал 1 159 кадров и штатно завершил сеанс.

На отдельном Android 15 тот же подписанный APK передал видео 1280×720 и принял касание во всех пяти профилях. Сеанс 4.1 продолжался больше минуты и завершился штатно. При проверке приборки HSD передал поворот направо через 180 м, улицу и название трека. Согласование ключа и форматы шифрования отдельно сверены с Java JCE.
