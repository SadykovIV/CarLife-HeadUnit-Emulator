CarLife HeadUnit Emulator 0.5.1 для Windows x64 · 13 ноября 2026 года

1. Распакуйте ZIP целиком в обычную папку. Не запускайте приложение внутри ZIP.
2. Откройте CarLifeHeadUnitEmulator.exe. Python и Qt устанавливать отдельно не требуется.
3. Выберите USB-устройство в верхней панели и нажмите «Подключить».
   Режим AOA используется автоматически для выбранного устройства.
   Для проверки изображения, звука и управления без устройства выберите «Демо».

Wi-Fi
1. Подключите компьютер и телефон к общей сети или компьютер к точке доступа телефона.
2. В HeadSwap включите беспроводное ожидание. В HeadSwap Desktop 0.6.0:
   «Тип подключения» → «Wi-Fi» → «Подключить»; разрешите запрошенные права.
3. В эмуляторе сверху выберите Wi-Fi → «Найти», выберите IP и нажмите «Подключить».
   Можно сразу вписать IP телефона вручную. Порты задавать не требуется.
4. Если брандмауэр запросит доступ к локальной сети, разрешите его для этой сети.
   Обнаружение использует UDP 7999/8999; проекция — TCP 7240,8240,9240,9241,9242,9340.
   При изоляции Wi-Fi-клиентов используйте другую сеть или точку доступа телефона.
Wi-Fi не требует WinUSB, USB-кабеля или отладки ADB. Bluetooth/Wi-Fi Direct
согласование автомобильной ГУ не реализовано: нужна уже установленная общая сеть.
Режим TCP оставлен для одиночного лабораторного потока; для телефона выбирайте Wi-Fi.

Мультитач и обложки
Сенсорный экран передаёт отдельные контакты. Legacy dual — два пальца;
Action3 для совместимых устройств — до четырёх. Alt+мышь и Ctrl+колесо доступны
без сенсорного экрана. В приборке и HUD отображается полученная от плеера
обложка JPEG/PNG; при отсутствии изображения предыдущая обложка убирается.
Воспроизведение музыки и голосовых подсказок продолжается, пока окно эмулятора
обрабатывает жесты и перерисовывает проекцию.

USB на Windows
Для доступа libusb интерфейс выбранного USB-устройства должен использовать
совместимый драйвер (обычно WinUSB). Обычный Android-драйвер ADB сам по себе
не гарантирует доступ. Для обычного режима до AOA и accessory после AOA могут
потребоваться разные привязки драйверов. Обычное «Подключить» драйверы не меняет.
Не заменяйте драйвер составного Samsung USB-устройства целиком или драйверы
MTP, ADB, модема, USB-контроллера и концентратора: это может нарушить работу
других функций телефона. Сначала сохраните отчёт ниже.
В режиме 18d1:2d01 у телефона две разные функции: CarLife/AOA и ADB.
При подключении эта сборка сверяет номер интерфейса и его реальные bulk-каналы
через WinUSB. Путь ADB не используется для проекции, даже если Windows
проиндексировала его как интерфейс 0. Если доступен только ADB, ошибка
подключения ожидаема: это не повод заменять драйвер телефона целиком.
Документация: https://github.com/libusb/libusb/wiki/Windows

Настройка WinUSB из приложения
Если на этом ПК CarLife уже подключается через фактические каналы AOA,
переустановка не нужна. Просто нажмите «Подключить».

1. Выберите в верхней панели USB и нужный аксессуар 18d1:2d01. Завершите
   активную сессию и закройте другие программы, использующие эту функцию:
   даже проверка кратковременно инициализирует её через WinUSB.
2. Откройте «Приборка и HUD» → «Драйвер Windows» → «Настроить WinUSB…».
   Приложение заново идентифицирует устройство на выбранном физическом
   порту и проверяет интерфейс. Эта проверка сама не устанавливает драйвер.
3. Только если найден отдельный стандартный аппаратный ID CarLife MI_00 и
   подтверждена отдельная функция ADB, появится предложение назначить
   системный Microsoft WinUSB либо зарегистрировать путь уже назначенного
   драйвера. Проверьте порт/ID в диалоге. Можно нажать «Отмена».
4. После подтверждения Windows может показать UAC для CarLifeWinUsbSetup.exe.
   Это отдельный нативный помощник из данного ZIP; Python и основное
   приложение не повышают свои права. Помощник не подписан Authenticode,
   поэтому издатель в UAC может быть неизвестен. Сверьте SHA256 ZIP перед
   использованием. Помощник не добавляет сертификатов, не отключает проверку
   подписей и не устанавливает драйверы для составного родителя, MTP или ADB.
5. Если Windows потребует переподключение/перезагрузку, выполните его и снова
   выберите устройство. Успех подтверждается проверкой реальных каналов AOA.

Если есть только нестандартные узлы Samsung &ADB / &MS_COMP_MTP без
подтверждённого MI_00, помощник не подменяет их. Если Windows не предлагает
проверенный системный пакет WinUSB, запросите у поставщика подписанный пакет
для конкретного USB\VID_18D1&PID_2D01&MI_00. Не назначайте WinUSB устройству
18d1:2d01 целиком. Режим 18d1:2d00 с одной AOA-функцией — иной ID, помощник
этой версии для него драйвер не устанавливает. Установка на accessory ID
также не решает доступ к телефону в обычном режиме до перехода в AOA.

Как снять отчёт о неудачном подключении
1. Распакуйте эту версию в отдельную папку и закройте другие копии эмулятора.
2. Выберите USB и нужное устройство в верхней панели. Один раз нажмите
   «Подключить» и дождитесь результата.
3. Откройте вкладку «Диагностика» → «Экспорт отчёта» и сохраните JSON.
   «Папка сессии» открывает материалы этой попытки. По умолчанию они находятся
   в %LOCALAPPDATA%\CarLife HeadUnit\sessions\<сессия>\desktop-summary.json.
4. Укажите версию Windows, модель телефона, что показывает верхняя панель
   после ошибки и менялось ли устройство при переподключении. Исходный этап
   ошибки ищите в отчёте, а не в уже обновившемся списке USB. Перед отправкой
   проверьте отчёт: он может содержать локальные пути и данные текущей сессии.
   Для ошибки выбора функции Windows посмотрите connection_failure.selection_reason:
   adb_only означает, что Windows предоставила только ADB, а no_winusb — что
   подходящий путь WinUSB у выбранного аксессуара не найден. При успешной
   проверке сведения о каналах находятся в transport.windows_selection.verified.

Проверка на Windows
Запустите Verify.cmd из командной строки: он проверит импорты Qt/PyAV,
наличие libusb и H.264-кодеков, без открытия USB и без смены его режима.
Для отдельной проверки USB-библиотеки запустите VerifyUsbRuntime.cmd:
он проверит SHA256 и версию комплектной DLL, её экспортируемые функции,
импорт модулей обработки USB, доступность системных функций Windows/WinUSB,
инициализацию libusb, перечисление устройств и закрытие контекста. Отчёт:
%TEMP%\carlife-libusb-check.json. Этот тест не открывает выбранный телефон,
не захватывает интерфейс и не отправляет запросы AOA. PASS не подтверждает,
что драйвер конкретного телефона позволяет открыть его. Драйверы не меняются.
Локальная проверка приложения:
  CarLifeHeadUnitEmulator.exe --demo --smoke-test 8 --data-dir "C:\Temp\CarLife-Smoke"
Результаты: smoke-report.json и smoke-window.png в указанной папке.

Настройки и записи сессий: %LOCALAPPDATA%\CarLife HeadUnit
Папка сохранена для совместимости с версией 0.3.0.
При ошибке запуска: %LOCALAPPDATA%\CarLife HeadUnit\startup-error.txt
Снимки экрана и отчёты доступны из приложения.

Сборка проверяет SHA256 официального Python и всех wheel-пакетов, а также
формат AMD64 PE32+ каждого Windows-модуля. Факт запуска на Windows и тест
реального устройства подтверждаются отдельно: см. build-info.json.
EXE не подписан Authenticode; Windows может показать предупреждение издателя.
CarLifeWinUsbSetup.exe собран с заголовками MinGW-w64 v13.0.0; версия,
исходный commit и контрольная сумма архива заголовков указаны в build-info.json.
В ZIP нет установщика Zadig, внешнего пакета драйверов или сертификата.
